# MultiChat + озвучка (Twitch, YouTube, TikTok, Kick)

Поточна версія: **1.8.2**. Номер версії задається в `package.json`; застосунок автоматично показує його внизу лівої панелі. Для майбутнього релізу онови це поле за SemVer - інтерфейс підхопить його автоматично.
Нумерація версій: з появи віджета чату для OBS (раніше це була 1.3.42) версії рахуються як 1.4.x, і це 1.4.0. Старі номери 1.3.42 і новіші замінено за формулою 1.4.(N − 42): 1.3.42 → 1.4.0, 1.3.43 → 1.4.1, 1.3.50 → 1.4.8, 1.3.58 → 1.4.16, 1.3.65 → 1.4.23, 1.3.70 → 1.4.28. Версії до 1.3.42 лишились зі старими номерами. Кожна нова функція чи виправлення збільшує останнє число (наступна версія 1.4.30).

Широкий логотип у шапці інтерфейсу зберігається в `public/assets/multichat-wordmark.png`. Іконка вікна та Windows-збірки - `assets/icon.ico`.

Один чат з усіх платформ, озвучка (є українські жіночі голоси), події, лічильники глядачів, статус підключення
і режим для панелі OBS. Єдині стилі тексту застосовуються до налаштувань, чату, підказок, сповіщень і вікон входу; світла палітра відповідає світлій темі Windows. YouTube-емодзі й кастомні емодзі каналів відображаються за зображеннями, які передає конектор; режим озвучення може їх пропускати. TikTok-стікери й подарунки відображаються зображеннями в чаті програми та в OBS; для подарунків використовується розширена інформація конектора. Для Twitch доступне відображення емотів BetterTTV, 7TV та FrankerFaceZ з окремими перемикачами в налаштуваннях.
TikTok-стікери й подарунки відображаються зображеннями в чаті програми та в OBS; для подарунків використовується розширена інформація конектора.

## Швидкий старт

### Варіант А - програма для Windows (MultiChat.exe)
1. Один раз збери її: двічі клікни **`build-exe.bat`** (потрібні Node.js 18+ та інтернет, збірка 2-5 хв).
   Готова програма: папка `dist\MultiChat-win32-x64\`, запускай `MultiChat.exe` в ній (папку можна скопіювати куди завгодно).
   Не хочеш ставити Node.js? Завантаж проєкт на GitHub: вкладка Actions, Build MultiChat, Run workflow, завантаж артефакт `MultiChat-win`.
2. `MultiChat.exe` відкриває власне вікно. Закриєш вікно, і програма вимкнеться. Поки вона працює, чат доступний і для OBS на http://localhost:3000.
3. Поруч з `MultiChat.exe` створюються папка `voices` (офлайн-голоси) і `log` (журнали). Налаштування (`settings.json`), ключі (`config.json`), акаунти (`accounts.json`) і налаштування віджетів та розіграшів зберігаються в `%APPDATA%\MultiChat`, тому нова збірка чи версія в іншій папці їх не стирає. Старий `settings.json` поруч із програмою переїжджає туди сам.
4. Вхід через Google, Twitch чи Kick відкривається в твоєму звичайному браузері (Google не пускає вхід у вікнах програм); після входу повертайся у вікно MultiChat.
5. Windows SmartScreen може попередити про невідомого видавця (файл не підписаний): «Додаткові відомості», потім «Все одно виконати».

### Варіант Б - через Node.js
`npm install`, потім `npm start` (або двічі клікнути `start.bat`), далі http://localhost:3000

## Як влаштовані налаштування
Ліва панель поділена на гілки за темами. У кожній гілці налаштування згруповані в підрозділи-кнопки, стан розгортання запам'ятовується; угорі є кнопки «Розгорнути все» і «Згорнути все»:
- **Підключення:** підрозділ «Стрімінгові сервіси», а в самому його низу кнопка «🔑 API-ключі», що відкриває вікно з ключами для кнопок «Увійти» (кнопку видно, лише коли ввімкнено перемикач ключів); у заголовку видно, скільки платформ підключено;
- **Озвучка:** перемикач «Озвучувати чат» і підрозділи «Голос і звук» (голос, офлайн-голоси, швидкість, висота, гучність, тест),
  «Що озвучувати» (нікнейм, команди, згадування, символи, посилання, платформи) і «Обмеження і винятки» (довжина, черга, префікс, заборонені слова, глядачі-винятки);
- **Події в чаті:** перемикачі «Показувати події в чаті» й «Озвучувати події», а також підрозділ «Налаштування типів подій»;
- **Для OBS:** підрозділ «Параметри панелі OBS» з підказкою, як додати панель у OBS, і підрозділ «Налаштування панелі OBS», де окремими блоками зібрано тему панелі, час біля повідомлень, прокрутку чату й навантаження (CPU, RAM, GPU);
- **Програма:** підрозділи «Продуктивність» (разом із режимом запуску), «Звук втрати інтернет-з'єднання», «API-ключі» та «Для розробників» із діагностикою Kick.

## Підключення акаунтів
Біля кожного сервісу є поле для ніка і кнопка **«Увійти»** (додатковий спосіб авторизації).

| Платформа | Спосіб 1 (без ключів) | Спосіб 2: кнопка «Увійти» |
|---|---|---|
| Twitch | нік каналу (наприклад `imakcoc`) | OAuth: додає фоли, нагороди за бали, Hype Train |
| YouTube | `@handle` або посилання на стрім | вхід через Google: автопідключення за твоїм каналом, нові підписники |
| Kick | нік каналу | OAuth: підтягує нік каналу |
| TikTok | `@нік` акаунта | у MultiChat.exe кнопка «Увійти» відкриває вікно входу в акаунт TikTok (ключі не потрібні, див. нижче); чат однаково підключається за ніком |

Щоб кнопки «Увійти» працювали, один раз додай ключі в блоці **«Ключі для кнопок Увійти»** (Client ID і Secret).
Redirect URI показується прямо там, він має збігатися з тим, що ти вкажеш на сайті сервісу:
- Twitch: https://dev.twitch.tv/console (Client Type: Confidential)
- Google: https://console.cloud.google.com, увімкни YouTube Data API v3, створи OAuth client (Web application), у режимі Testing додай свій акаунт у Test users, а для стабільного доступу натисни Publish app
- Kick: https://kick.com/settings/developer (потрібна 2FA)

**TikTok і помилка «Failed to sign request»:** для підключення TikTok потрібен зовнішній сервер підписів Euler Stream. Особистий API-ключ не обов’язковий:
без нього використовується безкоштовний ліміт Euler Community, а MultiChat автоматично повторює підключення після тимчасової помилки. Особистий ключ Euler Stream можна
додати у блоці «Ключі для кнопок Увійти», рядок TikTok, лише якщо потрібно підвищити ліміти. Без доступу до сервера підписів жодна версія конектора не може відкрити TikTok WebSocket.

Ключі зберігаються в `config.json` у папці `%APPDATA%\MultiChat` (до 1.4.6 - поруч із програмою). Після підключення застосунок сам з'єднується зі стрімами, щойно ти в ефірі, і так само при кожному запуску.

## Статус і лічильники
- Угорі значки платформ з логотипами й текстом **Онлайн** (стрім в ефірі) або **Офлайн** (стріму немає). Крапка знизу показує підключення
  до чату: зелена - підключено, жовта - підключення, синя - очікування стріму, червона - помилка, сіра - не підключено.
  Червона крапка зверху - LIVE. Клік по значку ховає або показує повідомлення платформи.
  Як визначається ефір: Twitch - публічний запит раз на 30 с; YouTube - після входу через API, інакше зі сторінки каналу; під час ефіру статус YouTube повторно перевіряється раз на 30 с, щоб вчасно показати завершення; TikTok - перевірка
  перед підключенням; Kick - публічний API (якщо Cloudflare його блокує, значок оновлюється лише за подіями чату).
- Внизу чату лічильники глядачів: іконка платформи і кількість (0 показується як 0), після `|` загальна кількість.
  Джерела: TikTok (подія кімнати), Twitch (публічний запит, раз на 30 с), YouTube (API після входу, інакше сторінка відео),
  Kick (публічний API, раз на 45 с). Частина джерел неофіційна й може змінитися.
- У «Налаштування чату» → «Лічильники онлайну» доступно 8 режимів показу: платформи, загальний онлайн і Max online в усіх комбінаціях, зокрема повне приховування. Max online - найбільша зафіксована сума глядачів на активних платформах: значення зберігається після завершення стрімів і скидається з початком нового. Вибір режиму синхронізується з панеллю OBS.
- Блоки-підказки та інструкція OBS згортаються; стан запам'ятовується.

## Події (подарунки, підписки, фоли...)
Показ і озвучку кожного типу окремо вмикає таблиця в блоці «Події», є і загальні перемикачі «Показувати події в чаті» та «Озвучувати події».
| Платформа | Події |
|---|---|
| Twitch | підписки, подарунки, рейди, біти; після входу ще фоли, нагороди за бали, Hype Train |
| YouTube | нові учасники каналу; після входу нові підписники (раз на хвилину, поки йде стрім; приховані підписки не видно) |
| TikTok | подарунки, фоли, підписки, репости («поділився(-лась) стрімом»); лайки й заходи глядачів не показуються (це спам) |
| Kick | підписки, подаровані підписки, хости/рейди, нагороди за бали, фоли, Kicks (неофіційний канал, поля можуть змінюватись) |

## Озвучка (лише українська)
- **Онлайн:** Polina (жін., нейронний, Microsoft Edge TTS) і Google Translate (жін.); також Ostap (чол.). Через сервер, потрібен інтернет,
  доступ неофіційний; текст чату йде на сервери Microsoft або Google.
- **Офлайн (Piper):** Tetiana (жін., висока якість, ~115 МБ) і Lada (жін., проста, швидка, ~21 МБ).
  Блок «Офлайн-голоси (завантаження)», кнопка «Завантажити»: рушій і голос завантажуються в папку `voices` поруч із програмою
  (якщо в шляху є кирилиця, використовується `C:\ProgramData\MultiChat\voices`, бо Piper не відкриває такі шляхи).
  Інтернет потрібен лише для завантаження. Автовстановлення: Windows і Linux x64.
- **Не працює офлайн-голос?** Натисни «Перевірити голос» у блоці офлайн-голосів: покаже, де проблема (немає рушія, немає файлів, помилка запуску).
  Причину також видно в чаті, коли голос не спрацював.
- Системні голоси ОС: у Windows додай українську в Налаштування, Час і мова, Мовлення.
- **Виняток:** поле «Не озвучувати цих глядачів» (нікнейми через кому або з нового рядка). Швидко додати: наведи курсор на повідомлення й натисни 🔇.
  Виняток діє і для повідомлень, і для подій.
- Повзунок «Висота» діє лише на системні голоси; швидкість працює для всіх.
- **Що не озвучується:** команди (повідомлення, що починаються з `!`, також після згадування), згадування `@нік` (решта тексту читається повністю:
  «Привіт, @User123, як справи?» звучить як «Привіт, як справи?»), посилання, емодзі та зайві символи (`@ # * ~ < >` тощо), однакові повідомлення,
  що повторилися за кілька секунд. У нікнеймі `_` і `.` читаються як пауза. Усе вимикається галочками в блоці «Озвучка».
- **Озвучує лише одне вікно.** Якщо відкрито кілька (програма, вкладка браузера, панель OBS із `&tts=1`), говорить одне, інші мовчать, а вгорі пишеться,
  де зараз озвучка. Пріоритет: вікно, у якому ти востаннє клікав або тиснув клавішу; інакше вікно програми. Це прибирає ситуацію, коли одне
  повідомлення читають два голоси. Якщо онлайн-голос не спрацював, читає системний український голос, а за його відсутності повідомлення пропускається
  (англійський голос кирилицю не читає).

## Чат як панель в OBS
У застосунку є блок **«Для OBS»** з готовим посиланням і кнопкою «Копіювати» (`http://localhost:3000/?dock=1`).
Підказка «Як додати в OBS» розташована в «Параметрах панелі» й згортається. Застосунок має бути запущений. У панелі озвучка вимкнена (читає застосунок);
галочка в блоці додає `&tts=1`.

## Кнопки керування чатом
Унизу чату (також у панелі OBS) три кнопки: **Пропустити** (пропускає повідомлення, що озвучується зараз), **Очистити чергу** (прибирає все, що чекає озвучення)
і **Очистити чат** (очищає стрічку). Кнопки з панелі OBS керують вікном, яке озвучує. Смуги прокручування приховані і в панелі OBS, і в самому застосунку (чат, ліва панель), а гортати можна колесом миші, тачпадом або клавішами.

## Апаратне прискорення
Блок «Програма»: перемикач **Увімкнено / Вимкнено**. За замовчуванням **вимкнено** (з 1.4.5). Працює в програмі `MultiChat.exe` (у браузері налаштовується в самому браузері).
Зміна потребує перезапуску: з'являється кнопка «Перезапустити програму». Налаштування зберігається в `settings.json` поруч із програмою; якщо там нічого не вказано, прискорення вимкнено.
Якщо хочеш увімкнути прискорення для плавнішого інтерфейсу, ввімкни його в цьому блоці й перезапусти програму.

## Чат Kick
**Чому раніше працювало, а тепер ні.** Адреса й ключ Pusher у застосунку не змінювались від перших версій. Змінив усе Kick: він покинув хмарний Pusher,
тому старий публічний ключ тепер відповідає `App key ... not in this cluster (код 4001)` на кожному кластері, а новий шлюз `websockets.kick.com` вимагає
одноразового токена, який видається лише справжньому браузеру (Cloudflare).

**Як працює тепер (у програмі `MultiChat.exe`).** Застосунок відкриває сторінку чату Kick (`kick.com/popout/<нік>/chat`) у прихованому вікні вбудованого
Chromium і читає кадри її WebSocket через протокол DevTools. Сторінка сама отримує токен, підключається й підписується, а застосунок бере ті самі події
(повідомлення, підписки, подарунки, фоли, нагороди). Дані каналу (стрім в ефірі, глядачі) запитуються через ту саму сесію Chromium.
- Якщо Cloudflare попросить перевірку, у картці Kick з'явиться кнопка **«Показати вікно Kick»**: пройди перевірку, і вікно сховається саме.
- Збої не створюють нескінченного циклу: паузи між спробами ростуть (3, 6, 12... до 60 с); якщо чат довго мовчить (5 хв без жодного кадру), вікно відкривається заново.
- У режимі `npm start` у звичайному браузері читати чат Kick не вдається (немає вбудованого браузера): застосунок один раз пояснює це й перевіряє раз на 10 хв,
  замість того щоб без кінця перепідключатися. Для Kick запускай `MultiChat.exe`.

## TikTok: текст повідомлень і глядачі
- Текст береться з поля `comment`, а якщо TikTok змінить формат, шукаються схожі поля (`content`, `text`). Повідомлення без тексту в чаті не показуються,
  натомість один раз з'являється пояснення. Для діагностики: `set DEBUG_EVENTS=1 && npm start`.
- Лічильник глядачів оновлюється подіями кімнати. Якщо вони не приходять довше 45 с, лічильник береться з інформації про кімнату (раз на 30 с).

## Ключі в налаштуваннях
- Усі поля ключів за замовчуванням приховані (крапки). Кнопка-око біля поля показує або ховає лише цей ключ; значення не змінюється, стан видно по кнопці
  (перекреслене око приховано, підсвічене показано).
- Введені ключі лишаються в полях після збереження, входу й перезапуску (зберігаються в браузері або програмі), їх можна редагувати.
- **Очистити API-ключі:** після підтвердження видаляє ключі з полів, з пам'яті браузера і з `config.json`; токени доступу Twitch і YouTube теж прибираються
  (нік і канал лишаються, чат працює далі без входу), а підключення TikTok перезапускається без ключа Euler Stream. Автоматично ключі не відновлюються.

Якщо порт 3000 зайнятий, закрий іншу копію застосунку.

## Додаткові налаштування (група «Програма»: Продуктивність, Звук втрати інтернет-з'єднання)

**Пріоритет процесу** (Програма -> Продуктивність). Шість рівнів: Низький (Idle), Нижче звичайного, Звичайний (за замовчуванням), Вище звичайного, Високий, Реального часу. Для стримінгу достатньо «Звичайний» або «Вище звичайного». Змінюється пріоритет лише самої програми (вікно, вбудований браузер Kick), інші процеси Windows не чіпаються. Застосовується одразу, зберігається в `settings.json`. «Реального часу» перед увімкненням просить підтвердження: цей рівень може підвісити Windows і OBS, а без прав адміністратора Windows сама знижує його до «Високого» (програма покаже про це повідомлення).

**Запуск від імені адміністратора** (Програма -> Продуктивність -> Режим запуску). За замовчуванням звичайний запуск. Після зміни режиму потрібен перезапуск (кнопка в налаштуваннях). Якщо обрано режим адміністратора, Windows покаже вікно UAC. Якщо відмовити, програма запуститься у звичайному режимі й покаже пояснення; повторних запитів і циклічних перезапусків немає. Повернення зі режиму адміністратора до звичайного працює через перезапуск з кнопки в налаштуваннях. Доступно лише в `MultiChat.exe` на Windows.

**Звук втрати інтернету.** 15 вбудованих сигналів у 5 категоріях (тихі та короткі, стандартні, гучні, довгі, комбіновані), кнопка «Прослухати», гучність у відсотках (повзунок 0-100% і числове поле, крок 1%, окрема від гучності голосу бота; 0% - без звуку), перемикач «Увімкнути звук сповіщення», повтор кожні 3, 5, 10 або 30 с, поки інтернету немає (кнопка «Добре» у вікні сповіщення зупиняє повтор). Сигнал лунає одразу після втрати, не лунає під час відновлення і лунає знову, якщо інтернет зник повторно. Якщо звук вимкнено або гучність 0%, лишаються вікно і банер без звуку. Звук лунає лише у вікні програми, не в панелі OBS, і не перериває озвучення чату. Вибір зберігається після перезапуску.

## Гучність голосу бота (блок «Озвучення»)

Параметр «Гучність голосу бота (%)»: повзунок від 0% до 100% і числове поле, які змінюються разом (крок 1%, значення поза межами обмежуються до 0 або 100, дробові округлюються). 0% повністю вимикає звук бота (повідомлення не завантажуються й не звучать), 100% - максимальна гучність у застосунку. Зміна діє одразу, навіть на голос, що зараз звучить (крім системного голосу: його реплика дограє з попередньою гучністю, нова гучність діє з наступної), зберігається після перезапуску і застосовується до всіх голосів (Edge, Google, Piper, системні). Регулюється лише гучність самого застосунку: гучність інших програм Windows, системні звуки і звук сповіщення про втрату інтернету не змінюються. Старі збережені значення (частка 0..1) автоматично переносяться у відсотки.

## Мут глядача в панелі OBS

Іконка 🔇 біля повідомлення (з'являється при наведенні миші) тепер є і в чаті-панелі OBS, не лише у вікні програми. Клік у панелі OBS додає глядача до списку «не озвучувати» у вікні програми (воно зберігає список і озвучує чат), а клік у програмі передається в панель. Нік не дублюється, регістр не важливий. Прибрати глядача зі списку можна в блоці «Озвучка» у вікні програми. Якщо вікно програми не відкрите, клік у панелі OBS нікому не передається.

## Закриття програми

Закриття головного вікна повністю завершує програму: знищується і прихований браузер Kick, зупиняються процеси озвучення Piper, нові вікна й повторні підключення під час виходу не створюються. Якщо щось зависне, через 2,5 с програма завершується примусово.

## Показники навантаження (нижня панель чату)

У нижній панелі вікна програми, праворуч від лічильників глядачів (у самому правому куті), показуються CPU і RAM, наприклад «CPU 18% | RAM 62% (9,9 ГБ)». За замовчуванням це навантаження лише самого застосунку (усі його процеси: вікно, відео/GPU, прихований браузер Kick), у відсотках від усього процесора та пам'яті комп'ютера; обсяг пам'яті в дужках можна вимкнути, а також обрати один із двох форматів: «Використано» - «RAM 62% (9,9 ГБ)» «Використано і залишок» - «RAM 62% (9,9 ГБ, вільно 6,1 ГБ)» (залишок - вільна оперативна пам'ять усього комп'ютера) або «Використано і весь обсяг» - «RAM 62% (9,9/16 ГБ)» (весь обсяг - уся пам'ять, встановлена на ПК). До 1 ГБ використане показується в МБ, наприклад «1,5% (240 МБ)» або «1,5% (240 МБ/16 ГБ)». У налаштуваннях (Програма, Продуктивність) можна перемкнути на «Вся система» або повністю вимкнути показники.

Дані беруться з метрик процесів Electron/Chromium та модуля `os` (системні виклики Windows), без PowerShell/WMI і без прав адміністратора. Оновлення раз на 1,5 с. Збір працює лише поки є вікно, яке показує показники, і воно видиме; якщо показники вимкнено, вікно згорнуто або закрито, сервер нічого не вимірює. Одне вимірювання займає соті частки мілісекунди. Якщо даних немає (ще не надійшли, перестали надходити понад 6 с), показується «-». Кольори беруться зі змінних теми, тому читаються і в темній, і в світлій темі (контраст понад 4,5:1).

У вужчому вікні показники скорочуються ступінчасто, щоб лічильники глядачів не зсувались і панель не ставала вищою: спершу ховаються підписи CPU/RAM, потім залишок (а «9,9/16 ГБ» скорочується до «9,9 ГБ»), потім обсяг у дужках (лишаються відсотки), а у вікні вужчому за 825 пікс. показники ховаються зовсім. Пороги підібрано вимірюванням для найдовших значень.

## Права кнопка миші (копіювати, вставити)

У вікні програми працює контекстне меню (файл `contextmenu.js`):
- у полях введення (нік каналу, ключі API, списки): Скасувати, Повторити, Вирізати, Копіювати, Вставити, Виділити все;
- у чаті: на виділеному тексті «Копіювати»; на повідомленні без виділення «Копіювати текст повідомлення» і «Копіювати нік»; «Виділити весь чат» (потім Ctrl+C або права кнопка);
- на посиланні: «Відкрити посилання в браузері» і «Копіювати адресу посилання» (лише http/https);
- на іконці 🔇 меню не з'являється, щоб випадково не заглушити глядача.
Гарячі клавіші Ctrl+C, Ctrl+V, Ctrl+X, Ctrl+A, Ctrl+Z працюють як зазвичай.

### Показники в панелі OBS

Ті самі показники CPU/RAM показуються й у чаті-панелі OBS, в її нижній частині праворуч. Вимкнути їх можна в налаштуваннях програми, у групі «Для OBS», у підгрупі «Навантаження (CPU, RAM, GPU) в OBS»: «Як у програмі», «Показувати» або «Не показувати». Вимикач, а також режим («Лише застосунок» / «Вся система») і формат обсягу в дужках беруться з налаштувань програми й діють у панелі одразу, посилання в OBS копіювати заново не потрібно (панель OBS - окремий браузер зі своїм сховищем, тому програма передає налаштування панелі через сервер). Показ у програмі й показ в OBS вмикаються незалежно; коли вимкнено обидва, збір даних зупиняється повністю. Якщо панель OBS сховано (вкладка чи док згорнуті), вона теж не просить дані.

У вузькій панелі (типово 300-400 пікселів) показники не вміщаються в рядок із лічильниками й переходять на власний рядок праворуч під ними. Якщо й там тісно, довгі формати скорочуються ступінчасто (підписи CPU/RAM, залишок, «9,9/16 ГБ» до «9,9 ГБ», обсяг у дужках), аж до самих відсотків; пороги підібрано вимірюванням для найдовших значень. Якщо вікно програми закрите, панель працює з типовими налаштуваннями (лише застосунок, обсяг у дужках «Використано»).

## Інструкція з отримання API-ключів у програмі

У групі «🔌 Підключення», у «Стрімінгових сервісах» (внизу), кнопка «🔑 API-ключі» відкриває вікно «API-ключі (для кнопок «Увійти»)» (його видно, коли ввімкнено перемикач у «⚙️ Програма»), є кнопка «📘 Покрокова інструкція: як отримати ключі». Вона відкриває вікно з вкладками: «Загальне», «YouTube», «Twitch», «Kick» і «TikTok». Біля кожного сервісу в блоці ключів також є посилання «інструкція», яке відкриває вкладку саме цього сервісу.

Адреси повернення (Redirect URI) в інструкції підставляються автоматично з поточним портом програми й копіюються одним кліком; вони збігаються з тими, які надсилає сервер (`http://localhost:ПОРТ/auth/twitch|youtube|kick/callback`). Вікно закривається клавішею Esc, між вкладками можна ходити стрілками. Кроки звірено з документацією сервісів станом на жовтень 2026; важливі застереження: для YouTube застосунок у Google Cloud треба опублікувати (режим Testing скидає вхід кожні 7 днів), для Kick адреса повернення має містити `localhost`, а не `127.0.0.1`, для Twitch і Kick потрібна двофакторна автентифікація, а для TikTok офіційного входу немає.

## Підрозділ «API-ключі» і його перемикач

Перемикач «Використовувати API-ключі для кнопок «Увійти»» (за замовчуванням увімкнено) знаходиться в налаштуваннях «⚙️ Програма», у блоці «API-ключі». Поки галочка стоїть, у групі «Підключення» в самому низу «Стрімінгових сервісів» показано кнопку «🔑 API-ключі»: поля ключів, кнопки «Зберегти ключі» / «Очистити API-ключі» та покрокова інструкція. Коли галочку знято, цей розділ зникає з налаштувань.

Коли перемикач **вимкнено**:
- ховається кнопка «API-ключі» в «Стрімінгових сервісах» (і закривається відкрите вікно ключів) (поля ключів, кнопки збереження й очищення, інструкція) та кнопки «Увійти» біля сервісів, а підказка біля TikTok про відсутність входу зникає разом із кнопкою; «Вийти» перейменовується на «Відключити», щоб канал можна було відключити; сам перемикач у «Програмі» лишається, щоб його можна було ввімкнути знову;
- вимикаються функції: сторінки входу `/auth/...` відповідають відмовою (403), збереження й очищення ключів на сервері відхиляються, не використовуються збережені входи (події Twitch EventSub: фоли, нагороди, Hype Train; API YouTube: пошук трансляції, підписники, глядачі) і необов'язковий ключ Euler Stream для TikTok;
- чат працює далі за ніком чи посиланням на канал (Twitch, Kick, TikTok за ніком, YouTube за @handle, посиланням на канал чи трансляцію);
- збережені ключі й токени входу **не видаляються** (файли `config.json` і `accounts.json` не чіпаються), тож після ввімкнення все працює знову без повторного входу.

Стан зберігається в `settings.json` і діє на всі вікна одразу; платформи, що користуються входом чи ключем (Twitch, YouTube, TikTok), перепідключаються самі.

## «⚙️ Програма» → «Для розробників»: Діагностика Kick

У розділі «Програма» є вкладена гілка «Для розробників» (згорнута за замовчуванням). Вона містить службові функції для налагодження. Зараз у ній один пункт, **«Діагностика Kick»**, за замовчуванням **вимкнено**.

Коли її **ввімкнено**: біля Kick у «Підключенні» з'являється кнопка «Діагностика Kick» (така ж кнопка є й у самому розділі), яка відкриває сторінку `/api/kick-debug`: лічильники кадрів, події, які реально приходять від Kick, і журнал підключення. Сервер веде цей журнал (до 120 останніх записів) і друкує записи в консоль. Увага: у журнал можуть потрапити зразки повідомлень чату.

Коли її **вимкнено**: кнопки немає, сторінка діагностики відповідає відмовою (403), журнал не ведеться й нічого не друкується в консоль, а накопичений журнал стирається. Чат Kick працює так само незалежно від перемикача; лічильники кадрів і повідомлень у рядку статусу ведуться завжди. Змінна середовища `DEBUG_EVENTS` для розробників працює окремо від перемикача.

Стан зберігається в `settings.json`, діє на всі вікна одразу, не залежить від перемикача API-ключів.

## TikTok: статус «Онлайн» і кнопка «Показати вікно TikTok»
Статус Онлайн для TikTok ставиться, лише коли вбудований браузер стоїть саме на ефірі твого акаунта (`tiktok.com/@нік/live`). Якщо TikTok після відкриття вікна чи входу перекинув на чужий стрім або сторінку входу, статус лишається (або повертається) Офлайн, а чат чужого ефіру не читається й не озвучується. Через ~3 с поза ефіром акаунта програма скидає Онлайн і відкриває твій ефір заново.

Додатково статус Онлайн ставиться, лише коли сама сторінка TikTok підтверджує, що акаунт зараз у прямому ефірі. Без стріму сторінка `/@нік/live` усе одно має чат і WebSocket (чужі рекомендовані ефіри), тож раніше це давало хибне «в ефірі». Якщо акаунт не в ефірі, чат і кадри сторінки ігноруються, а сторінка раз на ~30 с перезавантажується, щоб дочекатися початку стріму. Якщо TikTok змінить формат сторінки й підтвердження не вдасться прочитати, програма працює по-старому (за чатом і WebSocket) і пише про це в консоль.

## Кнопки біля повідомлень у чаті
Біля кожного повідомлення при наведенні миші є 🔇: глядача додано до списку виключених з озвучки. Якщо повідомлення складається рівно з одного слова, поруч з'являється ще 🚫: слово додається до заборонених слів (блок «Озвучка»). Для довших повідомлень, команд (!), згадувань (@) і посилань цієї кнопки немає. Працює й у панелі OBS: список зберігає вікно програми. Увага: фільтр заборонених слів перевіряє входження в текст, тож коротке слово заблокує й усі повідомлення, де воно є частиною іншого слова.

## Розмір шрифту й щільність тексту чату
У «Налаштування чату» → «Вигляд» є повзунок «Розмір шрифту чату» з п'ятьма позиціями: стандартний розмір посередині (14 px у вікні програми, 13 px у панелі OBS), по два кроки менше й більше з обох боків (крок 2 px), число поруч показує розмір у пікселях і теж редагується. Нижче вибір «Щільність тексту»: Класичний (плоский, без заокруглень), Компактний (найщільніше), Звичайний (як було досі, за замовчуванням), Зручний (просторо). Налаштування застосовуються одразу в чаті програми й у панелі OBS.

Рядок під вибором щільності показує, що зараз застосовано (наприклад «Зараз у чаті: 14 px, щільність «Звичайний»»); якщо застосувати вигляд не вдалося, там буде текст помилки. Сторінка застосунку більше не кешується, тож вікно програми й панель OBS завжди беруть свіжу версію.

Кнопка «Скинути за замовчуванням» під налаштуваннями чату повертає стандартний розмір шрифту й щільність «Звичайний» (тема не змінюється).

TikTok: статус «в ефірі» більше не скидається, поки від TikTok надходять дані з WebSocket (до хвилини тому). Раніше тиха хвилина в чаті чи прихований чат (наприклад, розіграш) міг помилково дати «чат зник зі сторінки» і перепідключення раз на ~хвилину.

Kick: кнопка «Показати вікно Kick» тепер є в «Підключенні» у програмі в будь-якому стані Kick (раніше лише при помилці), поруч із «Діагностикою Kick». Якщо натиснути її в паузі між спробами підключення, вікно відкриється, щойно програма створить його знову. Вікно ховається саме, коли чат запрацює.

Кнопка «Показати вікно Kick» тепер вмикається в налаштуваннях, група «Для розробників», пункт «Кнопка «Показати вікно Kick»» (за замовчуванням вимкнено, як і для TikTok). Якщо Kick просить перевірку Cloudflare, а кнопку вимкнено, під повідомленням є підказка, де її ввімкнути.

Час біля повідомлень: у «Налаштування чату» → «Вигляд» пункт «Показувати час біля повідомлень» (за замовчуванням вимкнено) додає перед кожним повідомленням і подією час надходження у форматі години:хвилини. Діє одразу для всього чату, зокрема й для вже наявних повідомлень, і в панелі OBS. Повний час із датою видно у підказці при наведенні миші.

Групу налаштувань «OBS - чат у панелі» перейменовано на «Для OBS - налаштування панелі чату», а підрозділ «Параметри панелі» на «Параметри панелі OBS», щоб було ясно, що це налаштування для OBS.

У «Налаштування чату» → «Вигляд» функції розділено на окремі блоки з заголовками й лініями між ними: «Розмір шрифту чату», «Щільність тексту» (разом із кнопкою скидання розміру й щільності) та «Час біля повідомлень».

Група налаштувань «Для OBS - налаштування панелі чату» тепер називається просто «📺 Для OBS». У ній з'явилася підгрупа «Тема панелі OBS»: можна обрати «Як у програмі» (за замовчуванням, панель повторює тему програми) або власну тему й стиль для панелі, незалежно від теми програми. Зміна застосовується в панелі одразу.

Час біля повідомлень для панелі OBS налаштовується окремо: група «Для OBS», підгрупа «Час біля повідомлень в OBS» (Як у програмі, Показувати, Не показувати). За замовчуванням «Як у програмі»: панель повторює вибір програми; можна показувати час лише в програмі чи лише в OBS.

Покрокова інструкція з ключів більше не має вкладки «Чек-лист»; перелік джерел і примітка про дату перевірки тепер у кінці вкладки «Загальне».

Навантаження (CPU, RAM, GPU) у нижній панелі OBS тепер окрема функція: група «Для OBS», підгрупа «Навантаження (CPU, RAM, GPU) в OBS» з вибором «Як у програмі» (за замовчуванням), «Показувати» або «Не показувати», як і для часу й теми. Старий вимикач переноситься автоматично: вимкнений стає «Не показувати».

У підгрупі «Навантаження (CPU, RAM, GPU) в OBS» є вибір «Варіанти показу в OBS»: «Як у програмі» (за замовчуванням) або «Свої для OBS». У другому випадку з'являються ті самі варіанти, що й у блоці «Показники навантаження» програми: «Лише застосунок» / «Вся система», показ навантаження на відеокарту, пам'ять відеокарти (виділена, спільна, обидві) і обсяг у дужках, обсяг оперативної пам'яті в дужках і його формат. Значення панелі OBS не залежать від програми й навпаки. GPU-двигун спільний для обох, бо Windows опитує один двигун за раз. Дані GPU збираються, поки їх показує хоч одне вікно.

У налаштуваннях перший елемент усередині підгрупи (наприклад, випадайний список у «Навантаження (CPU, RAM, GPU) в OBS», «Тема панелі OBS» чи «Час біля повідомлень в OBS») більше не липне до лінії під назвою підгрупи: над ним є відступ.

Перевірка текстів (1.2.33): виправлено милозвучність («стрім в ефірі» замість «у ефірі»), «Не вдалося» замість «Не вдалось» у повідомленнях про токен Twitch і ID чату Kick, звертання «Перетягни» в підказці кнопки згортання (як в усьому інтерфейсі на «ти»), пропущене тире в описі щільності «Зручний».

Перевірка інтерфейсу (1.2.34): у вузькому вікні перемикач «Від імені адміністратора» більше не розриває слово посеред («адміністрато-ра»), посилання («створити застосунок», «інструкція») мають читабельний колір у світлих темах (Стандартна у світлому режимі, Light, Streamlabs OBS «День»), напис версії внизу налаштувань не показує застарілий номер до завантаження, а рядок «Зараз:» у пріоритеті процесу не пише «undefined». Також «Вмикайте» змінено на «Вмикай» (звертання на «ти», як в усьому інтерфейсі).

Режим запуску (запуск від імені адміністратора) перенесено з окремого підрозділу в «Продуктивність»: тепер це блок «Режим запуску» поруч із пріоритетом процесу. Функції не змінилися.

Тест сповіщення про втрату інтернету: у налаштуваннях «Програма» -> «Звук втрати інтернет-з'єднання» є блок «Тест сповіщення» з кнопкою «Імітувати втрату інтернету». Вона показує так, ніби інтернет зник: вікно з повідомленням (з позначкою, що це тест), червоний банер, стан «Немає мережі» біля платформ і звуковий сигнал (з повтором, якщо він увімкнений) за поточними налаштуваннями. «Добре» закриває вікно й зупиняє повтор. Імітація закінчується за 30 с або повторним натисканням кнопки («Зупинити імітацію»): тоді показується «Інтернет-з'єднання відновлено». Інтернет насправді не вимикається, сервер про тест не знає, а панель OBS його не показує. Якщо під час тесту інтернет справді зникне, тест зупиняється й діє справжній стан; поки справжня втрата триває, кнопка вимкнена.

Налаштування чату (1.2.37): з «Програма» в нову групу «🗨️ Налаштування чату» перенесено «Вигляд» (розмір шрифту, щільність тексту, час біля повідомлень), «Лічильники онлайну», «Смайлики Twitch» і «Тести подій і повідомлень». У «Програма» залишився блок «Тема» (тема й стиль). Самі функції не змінювалися.

Порядок налаштувань (1.2.38): групи йдуть за логікою користування - «Підключення», «API-ключі» (видно, лише коли ввімкнено ключі), «Озвучка», «Налаштування чату», «Для OBS», «Програма». «Події в чаті» тепер підблок «Налаштування чату» (перемикачі показу й озвучки подій та таблиця типів подій разом), далі «Вигляд», «Лічильники онлайну», «Смайлики Twitch», «Тести подій і повідомлень». У «Для OBS» порядок: параметри панелі, тема, час, навантаження. У «Програма»: тема, кнопка згортання, підказки, продуктивність, звук втрати інтернету, API-ключі, для розробників.

Імітація чату (1.2.39): вибір платформ розкладено у два рядки по дві (Twitch, YouTube / TikTok, Kick) - так само, як у блоці «Озвучувати з платформ».

Видалення офлайн-голосів (1.2.40): у блоці «Офлайн-голоси» біля кожного встановленого голосу є значок 🗑️ (із підтвердженням). Вона стирає файли голосу з комп'ютера; рушій Piper залишається, тож голос можна завантажити знову. Якщо видалено вибраний голос, програма переходить на інший встановлений офлайн-голос, а якщо його немає - на перший онлайн-голос. Голос, що озвучує зараз, дочекається кінця фрази й лише тоді видаляється.

Видалення голосу (1.2.41): замість червоної кнопки «Видалити» - простий значок 🗑️ без фону, з підказкою «Видалити голос» при наведенні.

Список офлайн-голосів (1.2.42): замість напису «✓ встановлено» - значок ✅ (підказка «Встановлено»). Кожен голос показано акуратно: зверху назва, під нею дрібніше мова, якість і розмір; справа ✅ і 🗑️ (або кнопка «Завантажити»). Текст більше не розривається по словах у вузькій панелі.

Прослуховування офлайн-голосів (1.2.43): біля кожного встановленого голосу є значок ▶️ - він озвучує коротку фразу цим голосом (повторне натискання або ⏹️ зупиняє). Прослуховування не змінює вибраний голос, іде окремо від черги озвучки і враховує швидкість та гучність бота (при 0% підкаже збільшити гучність). Внизу списку є підпис, що означає кожен значок: ✅ встановлено, ▶️ прослухати, 🗑️ видалити.

Відступи (1.2.44): у розгорнутих підблоках-підказках (зокрема «Офлайн-голоси (завантаження)») з'явився нижній відступ, тож кнопка «Перевірити голос» більше не притиснута до краю рамки.

Перевірка голосу (1.2.45): кнопка «Перевірити голос» у блоці «Офлайн-голоси» стала функцією для розробників. Її вмикає галочка «Кнопка «Перевірити голос»» у «Програма» → «Для розробників»; за замовчуванням вимкнено, кнопка й технічний звіт приховані. Після вимкнення звіт очищається.

Для розробників (1.2.46): під галочкою «Кнопка «Перевірити голос»» з'явився рядок статусу («Увімкнено: ...» або «Вимкнено: ...»), як під іншими пунктами цього розділу.

Нові офлайн-голоси (1.2.47): у «Офлайн-голоси» додано чоловічі українські голоси Piper - Mykyta і Oleksa (висока якість, по ~114 МБ, завантажуються з rhasspy/piper-voices разом з іншими голосами). Тепер офлайн-голосів чотири: Tetiana і Lada (жін.), Mykyta і Oleksa (чол.). Стать показується в списку голосів. Нових онлайн-голосів немає: Microsoft Edge TTS має для української лише два (Polina і Ostap, обидва вже додані), а Google Translate - один.

Edge TTS і системні голоси (1.2.48): виправлено помилку «Edge TTS WebSocket error: Unexpected server response: 200» (голоси Polina й Ostap) - Microsoft змінив Edge TTS наприкінці 2025, і старі версії бібліотеки msedge-tts отримують замість звуку HTML-сторінку. Вимога піднята до msedge-tts 2.0.5 або новішої; після оновлення запусти build-exe.bat (він виконає npm install) і перезбери .exe. Якщо помилка лишиться, текст підкаже, що саме оновити. Рядок «Системні голоси» прибрано зі списку голосів разом з повзунком «Висота (лише системні голоси)», який діяв лише для них. Якщо раніше був вибраний системний голос, програма сама перемкнеться на Polina.

Edge TTS, друге виправлення (1.2.49): 10-12 жовтня 2026 Microsoft знову змінив Edge TTS (новий сервер api.msedgeservices.com і новий формат токена), тому msedge-tts 2.0.x, зокрема 2.0.5, більше не працює. Вимога піднята до msedge-tts 2.1.0 або новішої. Щоб оновитися: запусти build-exe.bat (npm install підтягне нову версію); якщо в папці проєкту лишились старі node_modules або package-lock.json - видали їх і збери ще раз. Якщо онлайн-голос не спрацював, програма тепер сама читає запасним голосом (встановлений офлайн-голос Piper, потім Google Translate) і пише про це в чаті, а не пропускає повідомлення.

Edge TTS, пряме підключення (1.2.50): якщо нейронні голоси (Polina, Ostap) не працюють, сервер більше не залежить лише від бібліотеки msedge-tts. Він перевіряє встановлену версію: якщо вона 2.1.0 або новіша - пробує її, а при невдачі - власне підключення до нового сервера Microsoft (api.msedgeservices.com); якщо версія застаріла - одразу власне підключення. У тексті помилки в чаті тепер видно і причину, і встановлену версію msedge-tts, наприклад «[msedge-tts 2.0.4 - застаріла, потрібна 2.1.0+]». Власне підключення не перевірялося на живому сервері Microsoft, тому при невдачі текст помилки допоможе знайти причину.

Прокрутка чату в OBS (1.2.51): у «Для OBS» з'явився блок «Прокрутка чату в OBS» з галочкою «Дозволити прокрутку чату в панелі OBS» (за замовчуванням увімкнено, як було). Якщо вимкнути, чат у панелі OBS не прокручується колесом чи дотиком і завжди показує найновіші повідомлення внизу. Налаштування передається в панель одразу, як і «Час біля повідомлень».

TikTok після завершення стріму (1.2.51): у режимі вбудованого браузера статус «Онлайн» міг лишатися після кінця ефіру. Тепер кінець визначається надійніше: (1) повідомлення «ефір завершено» і «призупинено TikTok»; (2) раз на ~20 с програма питає TikTok про статус ефіру, і двічі поспіль «не в ефірі» перемикає на «Офлайн»; (3) екран «ефір завершено» на сторінці; (4) «живими» вважаються лише справжні повідомлення ефіру, а не службові кадри, які TikTok шле й після кінця, тож без повідомлень понад 90 с стрім вважається завершеним.

TikTok, статус після кінця стріму, друге виправлення (1.2.52): у режимі вбудованого браузера, поки статус «Онлайн», раз на ~25 с сторінка ефіру акаунта завантажується заново і з неї читається свіжий статус (ті самі дані, за якими визначається «в ефірі» при запуску); запасний варіант - запит до API TikTok. Двічі поспіль «не в ефірі» перемикає на «Офлайн», обнуляє лічильник глядачів і чекає наступного стріму. В описі статусу TikTok тепер видно результат останньої перевірки, наприклад «перевірка ефіру: в ефірі» або «не в ефірі, код 4»; якщо стоїть «відповідь не розпізнано», TikTok змінив формат сторінки. У режимі з бібліотекою tiktok-live-connector додано ще й перевірку статусу кімнати (код 4 = ефір завершено).

TikTok, «Онлайн» після відкриття вікна (1.2.53): якщо відкрити вікно TikTok, коли стрім уже завершено, сторінка показує «LIVE-трансляція завершилася» і чужі рекомендовані ефіри, а програма сприймала їхні кадри за ефір акаунта й ставила «Онлайн». Тепер екран кінця ефіру розпізнається за текстом (українською, російською, англійською; повідомлення глядачів у чаті не враховуються), і поки він на сторінці, «Онлайн» не ставиться, глядачі = 0, кадри чужих ефірів ігноруються. Якщо формат даних сторінки не розпізнано, статус ефіру з'ясовується свіжим запитом, а не за чужими кадрами.

TikTok, помилка «Failed to retrieve Room ID from all sources» (1.2.54): так бібліотека відповідає, коли не знаходить ефір (стрім не йде або TikTok блокує запит). Тепер це не помилка: у MultiChat.exe програма перемикається на режим вбудованого браузера, який точно знає, чи акаунт в ефірі, і чекає на початок стріму; без .exe просто показує «очікування початку стріму». Також повідомлення «The requested user isn't online» тепер теж розпізнається як очікування.

Перевірка ефіру TikTok, пояснення (1.2.55): напис «перевірка ефіру: відповідь не розпізнано» в описі статусу TikTok означає, що ні сторінка ефіру, ні запит до API TikTok не дали зрозумілого статусу, тому ця додаткова перевірка нічого не змінює. Тепер у дужках видно причину, наприклад «сторінка: HTTP 403; API: код 10201, без data» або «сторінка: у HTML немає даних сторінки». Кінець ефіру при цьому все одно визначається за іншими ознаками (екран «LIVE-трансляція завершилася», повідомлення про кінець, відсутність повідомлень ефіру понад 90 с).

Технічна інформація про підключення (1.2.56): тексти про вбудований браузер TikTok і Kick («чат TikTok (вбудований браузер)», «перевірка ефіру: ...», «чат Kick (вбудований браузер): кадрів ..., повідомлень ...», номери кімнат) більше не показуються в підказці значка платформи, картці платформи й повідомленні про підключення. Їх можна ввімкнути галочкою «Технічна інформація про підключення» в «Програма» → «Для розробників» (за замовчуванням вимкнено). Статуси очікування й помилки показуються як і раніше. Довідка про режим вбудованого браузера у вікні довідки (вкладка TikTok) не змінювалася.

Прості повідомлення про стан (1.2.57): у повідомленнях про очікування й перепідключення TikTok та Kick пояснення в дужках (на кшталт «на сторінці TikTok показано кінець ефіру», «TikTok не надсилає даних», «вбудований браузер аварійно завершився», текст помилки відлагоджувача) перенесено в технічну інформацію. Користувач бачить коротко, наприклад «⏳ TikTok: стрім завершено, очікую наступний». Причину, у дужках, видно після ввімкнення галочки «Технічна інформація про підключення» в «Для розробників».

## Розіграш: початок, кінець і тест

Учасники рахуються лише між кнопками «Почати розіграш» і «Закінчити розіграш» (після перезапуску програми набір треба розпочати знову). Кнопка «Тест розіграшу» на окремих тестових даних імітує весь розіграш: учасники пишуть у чат, набір закривається, обирається переможець (завжди власною генерацією, без Random.org). Твій справжній список під час тесту відкладається й повертається після «Зупинити тест».

## Віджет «Колесо фортуни» для OBS

«Налаштування чату» → «Для OBS» → «Віджети для OBS» → «Колесо фортуни». Це окреме колесо з секторами, які задаєш ти (не плутати з колесом у розіграшах, воно призначене для вибору переможця розіграшу).

- **Сектори:** кожен рядок у полі «Сектори» - окремий сектор. Формат: `Назва | вага | #колір` (вага й колір не обов'язкові), наприклад `Донат 50 грн | 2 | #ff5577`. До 40 секторів. З вагою більший сектор і більший шанс; вагу можна вимкнути, і всі сектори стануть однакові.
- **Крутити:** кнопка «🎡 Крутити в OBS» у вікні віджета (або «▶ Тест віджета» в мульти-віджеті). Переможця обирає програма випадковим числом з урахуванням ваги, а віджет лише показує обертання до цього сектора. Поки колесо крутиться, нова прокрутка не запускається. «▶ Пробне обертання» крутить тільки в перегляді вікна й нічого не відправляє в OBS.
- **Вибування:** якщо ввімкнено «Прибирати переможця з колеса», випавший сектор зникає після прокрутки. Кнопка «↺ Повернути сектори» повертає їх; зміна списку секторів теж повертає їх.
- **Вигляд:** палітри кольорів, обідок з лампочками, центр, три види стрілки (вона здригається на кожному секторі), шрифт і розмір тексту (довгі назви зменшуються й скорочуються самі), напис з результатом, підсвітка переможця, конфеті.
- **Звук:** клацання секторів і фанфари створюються самі, окремі файли не потрібні. Гучність налаштовується.
- **Поява:** колесо може бути видно завжди або з'являтися лише на час прокрутки.
- Як і в інших віджетів: профілі (кожен зі своїм посиланням `/fortune.html?p=ID` і своїми секторами), посилання для джерела «Браузер», перегляд, що оновлюється одразу, «Зберегти» для застосування в OBS. Колесо можна додати шаром у мульти-віджет.

## Розіграш: віджети переможця для OBS (у кожного розіграшу свій)

У кожному розіграші (По слову, Колесо фортуни, По квиткам, Угадай слово, По командам) є картка «Віджет для OBS» зі своїм посиланням `http://localhost:ПОРТ/winner-widget.html?cat=...`. Додай його в OBS як «Браузер» розміром 1920×1080 (фон прозорий). Кожен віджет показує лише переможців свого розіграшу й має власні налаштування: текст, шрифт (будь-який із встановлених на комп'ютері), розміри, кольори, появу, ефект, тривалість, звук (фанфари, дзвіночок, барабанна дріб, файл з комп'ютера або посилання), гучність і автопоказ. Налаштування, звуковий файл (папка `sounds`, окремий файл на розіграш) і посилання не залежать від інших розіграшів. «Налаштувати віджет» відкриває вікно з попереднім переглядом саме для вибраного розіграшу, «Тест ефектів і звуку» програє показ.

Після справжнього жеребкування переможець сам з'являється у віджеті свого розіграшу (якщо не вимкнено автопоказ); «Показати переможця» і «Сховати» керують показом вручну. Тест розіграшу на стрім не потрапляє.

Квиток, що розривається (квиток з перфорацією труситься, розривається по лінії, і з-під нього виходить переможець, у момент розриву чути шурхіт паперу) існує лише у віджеті розіграшу «По квиткам»: його групу налаштувань (вимкнути квиток, звук розриву, кольори паперу, тексту й акценту) і кнопку «Тест квитка» видно лише там. В інших розіграшах віджет показує звичайну картку.

Якщо раніше у програмі був один спільний віджет, при першому запуску його вигляд і звуковий файл копіюються в кожен розіграш (квиток лишається тільки в «По квиткам»), а старе посилання без `?cat=` і далі працює: показує переможців усіх розіграшів зі їхніми налаштуваннями. Налаштування лежать у `settings.json` поруч із програмою.

## Журнали платформ (папка log)

Для кожної платформи (Twitch, YouTube, TikTok, Kick) програма веде журнал підключення в папці `log` поруч із програмою. На кожен запуск програми для платформи створюється новий файл, підписаний платформою, датою (ДД.ММ.РРРР) і часом: `twitch_30.10.2026_14꞉03꞉11.log`. У часі стоїть не справжня двокрапка, а схожий на неї символ «꞉»: справжню двокрапку Windows в іменах файлів не дозволяє. Журнали старші за 7 днів (за часом останнього запису) видаляються автоматично при запуску програми й далі кожні 6 годин, файл, у який зараз пишеться, не чіпається, а чужі файли в папці `log` теж. Назви файлів із попередніх версій (`twitch.log`, `tiktok_2026-10-29_20-54-07.log`) при запуску приводяться до нового вигляду. Якщо один сеанс дуже довгий і файл перевищує 5 МБ, далі пишеться наступний файл (з новою датою й часом), а попередній лишається цілим.

У журнали пишуться зміни стану підключення з причиною (підключення, чат працює, очікування, помилка), вхід і вихід з ефіру, а в TikTok ще причини переключення в офлайн (скільки тривав ефір і скільки секунд не було даних). Повідомлення чату в журнали не потрапляють.

Журнали вмикаються й вимикаються в групі «Для розробників» → «Вести журнали платформ» (за замовчуванням увімкнено). Там же кнопка «Відкрити папку log». Якщо схоже на кінець ефіру, а стрім ще йде, TikTok перевіряється швидко (через 8 с, до 3 разів поспіль) замість 30 с. Якщо дані від TikTok зупинились (понад 60-90 с), але перевірка ефіру (раз на ~25 с) каже «в ефірі», це вважається збоєм потоку даних, а не кінцем стріму: чат перепідключається за 3 с, а статус «в ефірі» не скидається (у журналі рядок «ПЕРЕПІДКЛЮЧЕННЯ ЧАТУ»). Якщо чат не повернувся за 30 с, показується «очікування». Папку `log` не публікуй у відкритому доступі.

## Розіграш «По квитках»

Квиток це нагорода за бали каналу. У вікні «По квитках» лише Twitch і Kick. У блоці «Квиток» вказується ціна (бали), і після «Почати розіграш» кожна куплена нагорода з такою ціною додає глядача до учасників. Купив кілька разів - більше квитків, і шанс виграти пропорційний їхній кількості. Необов'язкова «Назва нагороди» додатково фільтрує нагороди; вона потрібна, якщо Kick не надсилає ціну нагороди. Слова в чаті в цьому розіграші не рахуються. Повторне «Додати» вручну дає учасникові ще один квиток. Нагороди приходять лише після входу в акаунт платформи в «Підключенні» (для Twitch потрібен дозвіл на нагороди за бали).

## Чат з переможцем

Після того як переможця обрано, у блоці «Повідомлення переможця» внизу вікна розіграшу з'являється його окремий чат: спершу повідомлення, яким він записався, а далі все, що він пише в чаті цієї платформи (зберігається останніх 30, найновіше внизу, блок гортається). Доданий вручну переможець упізнається за ніком на будь-якій платформі. Під час тесту розіграшу цей чат не пишеться, а «Очистити список» його прибирає.

## Швидке вимкнення озвучення

У нижній панелі, одразу після «Max online», є кнопка з динаміком: у вікні програми і в панелі OBS (`/?dock=1`). Натискання вимикає озвучення чату (поточна фраза й черга замовкають одразу, значок стає червоним), повторне вмикає. Стан спільний: кнопка в панелі OBS керує озвученням у вікні програми (та сама настройка, що й галочка «Озвучувати чат» у розділі «Озвучка», вони синхронізуються), а вимкнення у вікні програми показується в панелі OBS. Якщо панель OBS озвучує чат сама (`&tts=1`), вона теж замовкає. Озвучення подій цією кнопкою не вимикається. Стан не зберігається в самій панелі: після її перезапуску вона бере його від вікна програми.

## Шифрування ключів і токенів

Секрети в `config.json` (client secret Twitch, Google, Kick, ключ Euler Stream) і `accounts.json` (refresh-токени Twitch і YouTube) програма зберігає на диску зашифрованими засобами Windows (DPAPI через Electron `safeStorage`). У файлі вони мають вигляд `enc:v1:...`, а client ID, логіни й ID каналів лишаються читабельними. Старі відкриті значення перетворюються на зашифровані автоматично при першому запуску, вручну нічого робити не треба. Нові ключі, які ти впишеш у програмі, теж шифруються при збереженні. Якщо вписуєш ключ у `config.json` вручну, просто запиши його звичайним текстом: після запуску програми він сам зашифрується.

Що це дає: файл, скопійований з диска (резервна копія, хмара, архів, GitHub, вірус, який лише краде файли), розшифрувати деінде не вдасться. Чого це не дає: шкідлива програма, що працює під твоїм же користувачем Windows, може звернутися до тих самих засобів Windows або прочитати ключі з пам'яті запущеної програми, тож від таких програм захищає лише антивірус і обережність.

Файли не переносяться між комп'ютерами й акаунтами Windows: якщо перенести програму, ключі доведеться ввести знову, а в акаунти ввійти ще раз (у вікні «API-ключі» тоді буде попередження). Поза MultiChat.exe (наприклад, `node server.js`) шифрування недоступне, і ключі лежать відкритими, як раніше. Старі резервні копії `config.json` і `accounts.json` з відкритими значеннями краще видалити.


Група «Для OBS» (1.3.32): підрозділи «Тема панелі OBS», «Час біля повідомлень в OBS», «Прокрутка чату в OBS» і «Навантаження (CPU, RAM, GPU) в OBS» об'єднано в один підрозділ «Налаштування панелі OBS» (окремі блоки із заголовками й лініями, як у «Продуктивності»). «Параметри панелі OBS» лишився окремо. Самі налаштування й їхня дія не змінилися, ідентифікатори полів ті самі.

Група «Для OBS» (1.3.33): підрозділ «Чат у панелі OBS» перейменовано на «Налаштування панелі OBS». Емодзі 📺 біля назви групи замінено на значок OBS (SVG, спрощений малюнок логотипу).

API-ключі (1.3.34): окрему групу «🔑 API-ключі» прибрано, її вміст перенесено в групу «🔌 Підключення» як підрозділ «API-ключі (для кнопок «Увійти»)» під «Стрімінговими сервісами». Він, як і раніше, видимий лише коли ввімкнено перемикач у «⚙️ Програма». Поля, кнопки й інструкція не змінилися, тексти підказок оновлено під нове розташування.

API-ключі, вкладена гілка (1.3.35): «API-ключі (для кнопок «Увійти»)» тепер не окремий підрозділ групи «Підключення», а вкладена гілка в самому низу підрозділу «Стрімінгові сервіси» (група в групі). Видимість, поля й кнопки не змінилися.

Вікно API-ключів (1.3.37): кнопку «🔑 API-ключі» (внизу підрозділу «Стрімінгові сервіси») збільшено й вирівняно по центру. Вікно ключів тепер відкривається поверх чату так само, як вікно розіграшу: виїжджає зліва направо, чат стискається праворуч, закривається кнопкою ✕ у куті, повторним натисканням кнопки «API-ключі» або клавішею Esc. Вікно інструкції відкривається поверх нього, і Esc спершу закриває лише його (так само для вікна підтвердження «Очистити API-ключі»). Вікно ключів і вікно розіграшу не показуються разом: вибір розіграшу закриває вікно ключів, а відкриття ключів закриває розіграш. Кнопка «Увійти» без ключів сама відкриває це вікно й ставить курсор у потрібне поле. Кнопку видно, лише коли ввімкнено перемикач ключів; його вимкнення закриває вікно. Поля й дані ключів не змінилися. У панелі OBS вікна немає.

TikTok без кнопки «Увійти» (1.3.38): у картці TikTok прибрано неактивну кнопку «Увійти» і підказку «TikTok не надає входу для читання чату», бо входу для читання чату в TikTok немає. Підключення, як і раніше, за ніком; у .exe лишається кнопка «Показати вікно TikTok», де можна увійти в акаунт TikTok або пройти перевірку. У Twitch, YouTube і Kick кнопки «Увійти» не змінилися.

Вхід у TikTok (1.3.39): у картці TikTok знову є кнопка «Увійти», і тепер вона працює (лише в MultiChat.exe). Натискання відкриває справжню сторінку входу TikTok (`tiktok.com/login`) в окремому вікні програми. Пароль вводиться на сайті TikTok, програма його не бачить і не зберігає. Вікно входу використовує ту саму сесію, що й приховане вікно чату, тому після входу чат читається вже з твого акаунта. Вхід визначається за cookie сесії: щойно він з'явився, вікно саме закривається, а TikTok перепідключається. Коли вхід є, кнопка називається «Увійти знову» (можна ввійти іншим акаунтом). Стан підтягується й після перезапуску програми. Кнопка не залежить від перемикача API-ключів. Якщо TikTok просить перевірку, її можна пройти у цьому ж вікні. «Відключити» відключає канал, але не виходить з акаунта TikTok у вбудованому браузері. У `node server.js` (без .exe) кнопки немає, бо немає вбудованого браузера.

Група «Для OBS» (1.3.40): «Параметри панелі OBS» (посилання, озвучка, підказка) більше не окремий підрозділ, а перший блок підрозділу «Налаштування панелі OBS», над темою, часом, прокруткою й навантаженням. У групі «Для OBS» тепер один підрозділ.

Перевірка TikTok (1.3.40): коли TikTok у вбудованому браузері показує капчу чи іншу перевірку, програма сама виявляє її (за елементами капчі на сторінці, двічі поспіль), відкриває вікно TikTok на передньому плані (значок на панелі завдань блимає), ставить статус «TikTok просить перевірку» і показує вгорі чату банер із кнопкою «Відкрити вікно перевірки». Банер і кнопка працюють і в чаті програми, і в панелі OBS (кнопка відкриває вікно на комп'ютері, де запущено MultiChat). Поки перевірка триває, чат не перезавантажує сторінку. Кнопка «🔑 API-ключі» (1.3.41): повторне натискання кнопки ховає вікно ключів (раніше воно лише відкривалося). Закрити можна й кнопкою ✕ або клавішею Esc. Кнопка «Увійти» без ключів, як і раніше, лише відкриває вікно.

Віджет чату для OBS (1.4.0): у групі «Для OBS» з'явився підрозділ «Віджети для OBS», у ньому блок «Віджет чату» (перший віджет). Це окреме джерело «Браузер» для OBS (сторінка `/chat-widget.html`) із прозорим фоном: на відміну від панелі чату, воно призначене для показу чату просто на сцені.

Налаштування (з 1.4.4 - 80 пунктів, групи): Розташування (знизу вгору чи згори вниз, вирівнювання, максимум повідомлень, зникнення через N секунд, відступи, ширина), Поява (анімація: виїзд, плавно, збільшення, відскок, без; швидкість появи й зникнення), Шрифт і текст (будь-який шрифт, встановлений на ПК, розмір, інтервал, колір, жирність, обведення й тінь), Ім'я і значки (колір імені: свій для кожного, колір платформи чи один; жирність і розмір, двокрапка, ім'я окремим рядком, значок платформи та його розмір, час), Фон повідомлення (плашка чи без фону, колір, непрозорість, заокруглення, відступи, рамка, смужка кольору платформи), Платформи (які показувати), Фільтри і смайли (ховати команди «!», посилання: показувати / прибирати / ховати повідомлення, ховати певних глядачів (боти) і слова, обрізання довгих повідомлень, смайли картинками (Twitch, Kick, YouTube, TikTok, 7TV/BTTV/FFZ) і їх розмір), Події (підписки, подарунки тощо з окремими перемикачами й кольором виділення). Кнопка «Очистити чат» в програмі очищує й віджет.

Налаштування зберігаються в `settings.json` (ключ `chatWidget`). Схему полів і перевірку значень веде сервер, тому форма й віджет завжди узгоджені.

Нік TikTok після входу (1.4.1): коли ти входиш в акаунт TikTok кнопкою «Увійти», програма сама читає нік акаунта (з даних сторінки TikTok, запасний шлях - запит passport), підставляє його в картку TikTok, зберігає й перепідключає чат; вікно входу після цього закривається. Якщо нік уже такий самий, лише перепідключається чат. Якщо нік не знайдено (наприклад, вікно закрили раніше), у журналі буде запис, а нік можна вписати вручну, як раніше.

Виправлення хибного «Онлайн» у TikTok (1.4.1): за журналом (після входу в акаунт сторінка TikTok не містить `liveRoomUserInfo`, а API відповідає кодом 19881007 без даних, тобто акаунт не в ефірі) програма помилково вважала стрім в ефірі, бо чат і WebSocket є й на сторінці без стріму (рекомендовані чужі ефіри). Тепер код 19881007 означає «не в ефірі», а коли формат сторінки не розпізнано, «Онлайн» не ставиться, доки не прийде відповідь на запит про ефір. Без стріму показується «акаунт не в ефірі, очікую початку стріму», а лічильник і чат з'являються лише в справжньому ефірі.

«Увійти знову» у TikTok (1.4.2): раніше, коли вхід уже був, TikTok просто кидав на головну сторінку. Тепер кнопка «Увійти знову» питає підтвердження, виходить з акаунта TikTok у вбудованому браузері (очищає дані сесії TikTok, яка використовується лише для TikTok) і відкриває сторінку входу заново (можна іншим акаунтом). Нік нового акаунта підставляється автоматично. Якщо вікно входу закрити без входу, чат TikTok перепідключається вже без входу, а кнопка знову називається «Увійти».

Віджет чату: профілі, панель поверх чату, живий перегляд (1.4.3):
- Налаштування віджета тепер відкриваються поверх чату (як API-ключі й розіграш: панель виїжджає зліва, чат лишається праворуч), а не окремим вікном. Закрити можна ✕ у куті, повторним натисканням «Налаштувати віджет чату» або Esc. Панелі ключів, розіграшу й віджета не показуються разом. Якщо є незбережені зміни, програма питає, чи відкинути їх.
- Профілі (сцени): у налаштуваннях і в панелі є список профілів. «＋ Новий» створює профіль зі стандартними налаштуваннями, «⧉ Копія» копіює поточний, «✏️ Назва» перейменовує, «🗑 Видалити» видаляє (останній профіль видалити не можна). Кожен профіль має власні налаштування й власне посилання `…/chat-widget.html?p=ID`: для різних сцен OBS додай джерело «Браузер» з посиланням потрібного профілю. «Тест у OBS» і «Зберегти» діють лише на вибраний профіль. Раніше збережені налаштування стали профілем «Основний».
- Перегляд оновлюється без перезапуску: віджет зберігає повідомлення і при кожній зміні (двокрапка після імені, значки, час, ім'я окремим рядком, шрифт, кольори, фільтри, події, смайли тощо) перебудовує вже показані повідомлення за новими налаштуваннями. Так само змінюються повідомлення в самому OBS після «Зберегти». У перегляді повідомлення не зникають за часом, щоб зміни було видно.

Віджет чату: безперервний тест і більше налаштувань (1.4.4):
- «Тест у OBS» тепер безперервний: зразки повідомлень з'являються в віджеті вибраного профілю, доки не натиснеш «■ Зупинити тест» (та сама кнопка в панелі налаштувань). Тест триває й після закриття панелі, а також для віджета, відкритого вже під час тесту. Кнопку тесту під кнопкою «Налаштувати віджет чату» прибрано, тест лишився в панелі.
- Нові налаштування (26): Розташування: плавне затухання краю зі старими повідомленнями. Поява: анімація зникнення (плавно, убік, зменшення, без) і спалах нового повідомлення з кольором. Шрифт і текст: відстань між літерами, вирівнювання тексту, регістр, курсив. Ім'я і значки: окремий шрифт імені, регістр імені, ім'я на кольоровій плашці, обрізання довгих імен, власний роздільник замість двокрапки (до 3 символів), формат часу (14:05, 14:05:30, 2:05 PM). Фон повідомлення: градієнт до другого кольору, розмиття фону, тінь плашки. Фільтри: ховати надто короткі повідомлення, ховати однакові повідомлення підряд від одного глядача. Виділення слів (нова група): повідомлення зі словами-тригерами (наприклад, твій нік) виділяються фоном, кольором тексту або обома. Події: вигляд події (рамка, заливка, смужка, без виділення), товщина рамки, значок події.

Вибір шрифту у віджетах (1.4.8): виправлено дві проблеми у віджеті чату й рядку, що біжить.
- Не можна було вибрати інший шрифт, поки в полі вписаний шрифт: стандартний випадний список браузера показував лише шрифти, що збігаються з текстом у полі, і погано прокручувався. Тепер власний список: при натисканні на поле завжди відкривається ПОВНИЙ список (поточний шрифт підсвічений і прокручений до середини), який прокручується колесом миші, а кожен шрифт показано власним накресленням. Набір тексту в полі фільтрує список, ↑ ↓ Enter вибирають, Esc спершу закриває лише список, а не панель. Для необов'язкового шрифту імені є пункт «(як у тексту)».
- Шрифтів було менше, ніж на ПК: список з сервера брався лише через GDI+, який бачить тільки системно встановлені шрифти й пропускає частину OpenType та шрифти, встановлені лише для твого користувача Windows. Тепер список об'єднує GDI+, WPF/DirectWrite (повний набір, зокрема шрифти користувача), реєстр шрифтів користувача й шрифти, які бачить сам браузер програми (`queryLocalFonts`). Якщо розширений запит не спрацює, використовується простий спосіб, як раніше. Список шрифтів оновлюється після перезапуску програми.
- Це стосується шрифтів у віджеті чату (текст і ім'я) та рядку, що біжить. Віджет переможців розіграшу має власний список шрифтів: він теж отримав ширший перелік із сервера.
- Важливо: шрифт показується в OBS, лише якщо він встановлений на тому самому комп'ютері, де працює OBS.
